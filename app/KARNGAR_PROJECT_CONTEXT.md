# KARNGAR PROJECT CONTEXT
## پروژه کارنگار — سند مرجع برای ادامه توسعه

> این فایل مرجع اصلی پروژه است.
> قبل از هرگونه تغییر در کد، این فایل را کامل بخوان.
> مسیر پروژه و تصمیمات قبلی را بدون دلیل تغییر نده.
> اگر چیزی در کد فعلی با این سند مغایرت داشت، ابتدا کد فعلی را بررسی کن و سپس تغییر را با کمترین ریسک انجام بده.

# 1. معرفی پروژه

نام پروژه:

کارنگار

نام قبلی پروژه:

CarLife

کارنگار یک سیستم «پرونده دیجیتال مادام‌العمر خودرو» است.

هدف اصلی:

برای هر خودرو یک پرونده دیجیتال ساخته شود که سوابق خودرو در آن ثبت شود و با تغییر مالک، پرونده و سوابق خودرو بتواند به مالک جدید منتقل شود.

ایده اصلی این است:

مالک خودرو فقط صاحب «خودرو» نیست؛
بلکه باید بتواند تاریخچه واقعی خودرو را ببیند.

پرونده خودرو باید در طول عمر خودرو باقی بماند.

# 3. اصل بسیار مهم محصول

مهم‌ترین مفهوم سیستم:

VEHICLE ≠ OWNER

خودرو باید یک موجودیت مستقل باشد.

مالک فقط مالک فعلی خودرو است.

بنابراین اگر خودرو فروخته شود:

مالک قبلی حذف نمی‌شود از تاریخچه.

پرونده خودرو هم نباید از بین برود.

مالک جدید باید همان پرونده را تحویل بگیرد.

مثال:

مالک اول:
علی

خودرو:
Lexus LS460L

سوابق:
10 سرویس
3 تعمیر
5 تعویض قطعه

خودرو فروخته می‌شود.

مالک دوم:
رضا

رضا باید همان خودرو و همان سوابق را ببیند.

نباید یک vehicle جدید ساخته شود.

باید ownership تغییر کند یا یک رکورد مالکیت جدید ایجاد شود.

این قابلیت یکی از پایه‌های اصلی محصول است و نباید در توسعه فراموش شود.

آیا دامنه Supabase باز می‌شود؟

mileage = 125000

دارد.

current_mileage = 85000

ولی service mileage = 125000

است.

نباید بدون تصمیم کاربر آن را اصلاح کرد.

# 57. اگر خطا رخ داد

اول خطای اصلی را پیدا کن.

مثلاً اگر Vite می‌گوید:

PARSE_ERROR

اول syntax را اصلاح کن.

اگر می‌گوید:

does not provide an export named 'default'

بررسی کن:

export default ComponentName;

وجود دارد یا نه.

اگر:

ERR_NAME_NOT_RESOLVED

برای Supabase آمد:

اول شبکه / DNS / Supabase URL را بررسی کن.

کد را بی‌دلیل تغییر نده.
